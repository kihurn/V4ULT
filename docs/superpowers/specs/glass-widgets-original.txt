# Glass widgets — build prompt

## Goal
You're building a single full-screen section: a cluster of four frosted-glass health widgets over a dramatic portrait
lit blue and orange. **Heart Rate** shows a live bpm with a scrolling ECG trace and a blinking LIVE dot,
**Respiration** shows breaths per minute with a ring that breathes in and out, **Light** shows a colour temperature in
kelvin with a marker on a scale, and **Ambient Noise** shows decibels with a bar waveform and a sweeping playhead. The
big numbers are striped (horizontal lines cut through the glyphs) and tick live: when a reading changes, its digits
roll like an odometer. The readings follow a fixed 5-second loop of changes. Match everything below exactly: layout,
type, colors, image and motion. Keep the copy and the image as given; the user swaps in their own content afterwards.

## Stack and setup
- Vite + React 19 + TypeScript (strict). Plain CSS: one global tokens file plus CSS Modules per component. No CSS
  framework and **no animation library**: every moving part runs on one shared `requestAnimationFrame` clock (Motion,
  M1), so the widgets stay in step with each other.
- Create and run:
  ```bash
  npm create vite@latest glass-widgets -- --template react-ts
  cd glass-widgets
  npm install
  npm run dev
  ```
- Folder layout:
  ```

  src/main.tsx                      renders <App /> in <StrictMode>, imports tokens.css and global.css
  src/App.tsx                       the section: portrait, cluster, preload, intro, feed (+ App.module.css)
  src/lib/clock.ts                  the shared clock and rAF loop, reduced-motion check
  src/lib/feed.ts                   the 5-second loop of readings
  src/lib/ease.ts                   easing curves
  src/lib/canvas.ts                 sizes a canvas to its box at the device pixel ratio
  src/lib/preload.ts                decodes the portrait and loads the font faces

  src/styles/global.css             reset, base styles, .sr-only
  ```

- Delete the scaffold's leftovers that aren't in this layout (`App.css`, `index.css`, `src/assets/`, the sample icons
  in `public/`). Make sure `"strict": true` is set in `tsconfig.app.json`.
- `index.html`: `lang="en"`, title "Glass widgets — Live vitals", meta description "Heart rate, breathing, light and
  ambient noise, live, on frosted glass.", `<link rel="icon" href="data:,">` (no favicon 404), the Inter stylesheet
  (Typography), and two image preloads: `<link rel="preload" as="image" href="…/portrait-wide.webp"
  media="(aspect-ratio >= 3/4)">` and `<link rel="preload" as="image" href="…/portrait-tall.webp"
  media="(aspect-ratio < 3/4)">`. The portrait is only ever loaded as an image (`<img>`, `<source>`, `new Image()`),

- Keep `<StrictMode>`. Every effect cleans up after itself (unsubscribe from the clock, disconnect observers, a

- Visual values live in `tokens.css`. Motion numbers live as named constants at the top of the file that uses them.

## Design tokens
**Scale.** All sizes below are design pixels: the concept is a 1080 × 1350 frame with the widget cluster, 640 × 610,
in its middle. One design px (`--u` on `:root`) is:
```css
--u: min(
  max(min(calc(100vw / 1440), calc(100svh / 760)), 1px),
  calc((100vw - 64px) / 640),
  calc((100svh - 64px) / 610)
);
```
So the cluster keeps its design size (1 design px = 1 CSS px) on ordinary desktop screens, grows with the screen above
1440 wide, and shrinks only when it wouldn't fit with a 32 px margin. Write every size as `calc(N * var(--u))` and
define the tokens below as lengths (e.g. `--col-w: calc(313 * var(--u))`). Exceptions in CSS px: the 1 px card rim, the
1 px scale line and ticks. Unitless: `--glass-saturate`, `--glass-bright`.

**Phone** (`@media (width < 640px), (height < 500px) and (pointer: coarse)`: narrow screens, and phones on their side):
the same cluster, scaled to fill the width with a 16 px margin (or the height, on its side), and small text gets a
readable floor. Override on `:root`:
```css
--u: min(calc((100vw - 32px) / 640), calc((100svh - 32px) / 610));
--label-size: max(calc(18.5 * var(--u)), 13px);
--unit-size: max(calc(19 * var(--u)), 12px);
--small-size: max(calc(15.5 * var(--u)), 11px);
--live-size: max(calc(13 * var(--u)), 9px);
--ring-size: max(calc(12.5 * var(--u)), 9px);
--live-dot: max(calc(5 * var(--u)), 4px);
```
At 375 × 667 that's a 343 × 327 cluster.

## Motion
All times in seconds. Every moving part reads the same clock. Easing curves are written out in `ease.ts`:
```ts
export const clamp01 = (x: number) => Math.min(1, Math.max(0, x));
export const quartOut = (x: number) => 1 - (1 - clamp01(x)) ** 4;                         // digit rolls
export const quartInOut = (x: number) => { const t = clamp01(x); return t < 0.5 ? 8 * t ** 4 : 1 - (-2 * t + 2) ** 4 / 2; }; // ring
export const quadInOut = (x: number) => { const t = clamp01(x); return t < 0.5 ? 2 * t * t : 1 - (-2 * t + 2) ** 2 / 2; };  // marker
export const smoothstep = (a: number, b: number, x: number) => { const t = clamp01((x - a) / (b - a)); return t * t * (3 - 2 * t); };
```

### M1 · Clock (the hard bit: one loop for everything)
`clock.ts` keeps one `requestAnimationFrame` loop and a set of frame callbacks:
```ts
type Frame = (t: number) => void;
const frames = new Set<Frame>();
let startedAt: number | null = null;
let raf = 0;
let visible = true;
export function start() { if (startedAt === null) startedAt = performance.now(); }
export function time() { return startedAt === null ? 0 : (performance.now() - startedAt) / 1000; }
export function setVisible(v: boolean) { visible = v; }               // M10
function loop() {
  if (visible) { const t = time(); frames.forEach((f) => f(t)); }
  raf = requestAnimationFrame(loop);
}
export function onFrame(f: Frame) {                                   // returns the cleanup
  frames.add(f);
  if (!raf) raf = requestAnimationFrame(loop);
  return () => { frames.delete(f); if (frames.size === 0) { cancelAnimationFrame(raf); raf = 0; } };
}
export const reducedMotion = () => window.matchMedia("(prefers-reduced-motion: reduce)").matches;
```
Clock time `t` is 0 until `start()` (called once the section is ready, M9). **Loop time** is `t − INTRO` with
`INTRO = 1`: the feed, the ECG beat, the LIVE dot, the ring and the playhead all use loop time, so they're in step.
Every component subscribes with `useEffect(() => onFrame(…), [])` and returns that cleanup.

### M2 · The feed: a 5-second loop of readings
`feed.ts` exports `LOOP = 5`, `INTRO = 1`, `START = { heart: 68, breath: 14, light: 2700, noise: 34 }` and these
events (loop time → new reading); the values at the end of the loop equal `START`, so it repeats seamlessly:
| at | reading | value |
|---|---|---|
| 0.8 | light | 3400 |
| 1.1 | heart | 69 |
| 1.4 | noise | 36 |
| 2.1 | breath | 15 |
| 2.2 | heart | 71 |
| 2.9 | noise | 38 |
| 3.0 | light | 2700 |
| 3.4 | heart | 70 |
| 4.4 | breath | 14 |
| 4.4 | noise | 34 |
| 4.45 | heart | 68 |

Two helpers, with `loops = Math.floor(lt / LOOP)` and `inLoop = lt − loops * LOOP`:
- `eventCount(lt)` = `loops * EVENTS.length +` the number of events with `at <= inLoop` (changes whenever an event
  fires);
- `feedAt(lt)` returns `{ readings, since }`: `readings` starts as a copy of `START` and takes every event with
  `at <= inLoop`; `since[metric]` is `loops * LOOP + at` of that metric's last applied event (0 if none). `since` is the
  loop time of the change, so a roll starts exactly on the event, not a frame later when React gets round to it.

App keeps `const [feed, setFeed] = useState(() => feedAt(0))` and, in its frame callback (M9), once `lt >= 0`:
`if (eventCount(lt) !== fired) { fired = eventCount(lt); setFeed(feedAt(lt)); }`. Each widget gets its reading and
`since = INTRO + feed.since[metric]` (clock time).

### M3 · Digit roll (the hard bit)
Trigger: the Ticker's value changes. Every digit rolls on its own from where it is now to its new digit, in the
direction of the change (value up: the strip moves up and the new digit comes in from below, passing through the
digits in between and wrapping 9 → 0; value down: the reverse). All digits of one change roll together over the same
duration (0.55, Light 0.7) with `quartOut`. A two-step change (34 → 36) is one continuous roll of two steps; 2700 →
3400 rolls the hundreds digit 7 steps (7 8 9 0 1 2 3 4) while the thousands digit rolls 1 step, both in 0.7 s.
State per digit, in a ref: `{ from, to, start, shown }` where positions are in digit steps (position 3 shows a "3";
3.4 shows the "3" moved 40% up and the "4" coming in below):
```ts
const mod10 = (n: number) => ((n % 10) + 10) % 10;
const pad = (v: number, n: number) => String(Math.round(Math.abs(v))).padStart(n, "0").slice(-n);
const position = (r: Roll, t: number, d: number) => r.from + (r.to - r.from) * quartOut((t - r.start) / d);

// on a new value (useEffect on [value, since, digits, duration]; keep the previous value in a ref and skip if equal)
const dir = Math.sign(value - prev);
const now = since ?? time();
const next = pad(value, digits);
rolls.forEach((r, i) => {
  const at = position(r, now, duration);
  const shift = 10 * Math.floor(r.to / 10);          // keeps the numbers small; the digits repeat every 10
  const cur = mod10(Math.round(r.to));
  const d = +next[i];
  const steps = dir > 0 ? mod10(d - cur) : -mod10(cur - d);
  r.from = at - shift;
  r.to = r.to - shift + steps;
  r.start = now;
  if (reducedMotion()) r.from = r.to;                 // jump, no roll
});

// every frame (onFrame), per digit i with glyph spans a (current) and b (next):
const p = position(r, t, duration);
if (p !== r.shown) {
  r.shown = p;
  const k = Math.floor(p), f = p - k;
  a.textContent = String(mod10(k));
  b.textContent = String(mod10(k + 1));
  a.style.transform = `translateY(${-f * 100}%)`;
  b.style.transform = `translateY(${(1 - f) * 100}%)`;
}
```
Initial render (before any frame): `a` shows the digit untransformed, `b` shows the next digit at `translateY(100%)`.
A new value in the middle of a roll simply re-targets from the current position. Initialise each digit's `from`/`to`
to its starting digit and `start` to 0.

### M4 · ECG (the hard bit)
The trace scrolls left at 141.6 px/s (design px); one beat every `BEAT = 5 / 6` s (118 px apart, 6 beats per loop).
Each beat is the sum of five Gaussian bumps `[height, offset from the R spike, width]` in design px (negative height =
up): P `[-5.5, -18, 3.2]`, Q `[7, -4, 1.0]`, R `[-46.5, 0.3, 1.6]`, S `[15, 5, 1.3]`, T `[-11, 29, 5.8]`. The R spike
reaches the head at loop time `R_AT = 0.105` and every BEAT after.
```ts
function trace(tau: number) {                    // tau = loop time; returns the height at that moment
  const ph = tau - R_AT;
  const dx = (ph - BEAT * Math.round(ph / BEAT)) * SPEED;       // px from the nearest R spike
  let y = 0;
  for (const [a, c, w] of WAVES) y += a * Math.exp(-((dx - c) ** 2) / (2 * w * w));
  return y;
}
```
Every frame, in design px on the canvas (281 × 90, scale `s = canvas.clientWidth / 281`; see `canvas.ts` below):
`lt = t − INTRO`, `head = 10 + 261 = 271`, baseline 60. Stroke a path for x from 10 to 271 in steps of 0.5 through
`(x, 60 + trace(lt − (head − x) / 141.6))`, `lineWidth 1.8`, round joins and caps, with a linear-gradient stroke from
`rgba(255,255,255,0)` at x 10 to opaque white at x `10 + 0.4 × 261` (the trace fades in over its left 40%). Then the
head dot: a circle of radius 4 at `(head, 60 + trace(lt))`, filled with the accent (read `--accent` from the canvas's
computed style) with `shadowColor` accent and `shadowBlur = 6 * s * dpr` (shadow blur isn't scaled by the transform),
then reset `shadowBlur` to 0.

`canvas.ts`, used by the ECG and the waveform:
```ts
export function surface(canvas: HTMLCanvasElement, designWidth: number) {
  const w = canvas.clientWidth, h = canvas.clientHeight;
  if (w === 0 || h === 0) return null;                          // skip frames while it has no size
  const dpr = Math.min(window.devicePixelRatio || 1, 3);
  const pw = Math.round(w * dpr), ph = Math.round(h * dpr);
  if (canvas.width !== pw || canvas.height !== ph) { canvas.width = pw; canvas.height = ph; }
  const ctx = canvas.getContext("2d");
  if (!ctx) return null;
  const s = w / designWidth;
  ctx.setTransform(dpr * s, 0, 0, dpr * s, 0, 0);               // draw in design px; reset every frame
  ctx.clearRect(0, 0, w / s, h / s);
  return { ctx, w: w / s, h: h / s, s, dpr };
}
```

### M5 · LIVE dot
Every frame: `opacity = 0.38 + 0.57 * pulse`, with `pulse = max(0, 1 − d / 0.117)` and `d` the distance in seconds from
loop time to the nearest beat at `0.117 + k × BEAT`. So the dot flashes from dim to bright peach and back in about a
quarter of a second, once per heartbeat, just after each R spike reaches the ECG's head.

### M6 · Breathing ring
Every frame, `lt = Math.max(0, t − INTRO) % 5` (so during the intro the ring rests at the loop's start: "IN" and the
dot). First half (lt < 2.5): the word is "IN" and the arc's fraction is `quartInOut(lt / 2.5)`; second half: "OUT"
and `1 − quartInOut((lt − 2.5) / 2.5)`. Set the arc's `stroke-dasharray` to `` `${(fraction * 100).toFixed(3)} 100` ``.
So the arc draws clockwise from 12 o'clock to a full circle while it says IN, holds, the word switches to OUT at 2.5,
and the arc undraws back toward 12 o'clock. Keep the word in React state (set it every frame; React skips unchanged
values).

### M7 · Light marker
Trigger: the reading changes. The marker slides from where it is to the new reading's place in 0.6 s with
`quadInOut`, starting at `since` (so it moves with the digits). State in a ref `{ from, to, start, shown }` (fractions
of the scale); on a change, `from` = the current position, `to` = the new fraction, `start = since ?? time()`; every
frame write `--at` on the marker when the position changed.

### M8 · Waveform (the hard bit)
118 bars, each `1.5` wide with round ends (`roundRect`, radius 0.75), centred at `x = (i + 0.5) × 378 / 118` and
mirrored around the canvas's middle (height 92). Every frame, `lt` = loop time:
```ts
function envelope(x: number, lt: number) {                      // 0…1
  const u = x - 43 * lt;                                        // the pattern drifts right at 43 px/s
  const taper = Math.sin((Math.PI * x) / 378) ** 0.5;           // smaller toward both ends
  const ripple = 0.66 + 0.34 * Math.sin((2 * Math.PI * u) / 37);
  const swell = 0.7 + 0.3 * Math.sin((2 * Math.PI * u) / 131 + 1.3);
  return taper * ripple * swell;
}
// bar height (total, centred on the middle line) = 12 + 78 * envelope(x, lt): 12 to 90
```
The playhead sweeps left to right once per loop: `head = (((lt % 5) + 5) % 5) / 5 × 378`. For each bar,
`d = min(|x − head|, 378 − |x − head|)` (the glow wraps from the right end round to the left): bars with `d < 7` are
the accent colour at alpha 0.9; the others white at alpha `0.4 + 0.4 × (1 − smoothstep(15, 45, d))` (bright around the
playhead, fading back to 40% by 45 px away). Reset `globalAlpha` to 1 after drawing.

### M9 · Load and intro
App runs the preload in an effect (with a cancelled flag): it waits for the portrait the screen will use (the tall one
if `matchMedia("(aspect-ratio < 3/4)")` matches, else the wide one) to decode (`const img = new Image(); img.src = url;
await img.decode()`, logging and ignoring a failure) and for each font face with `document.fonts.load('400 1em
"Inter"')`, `'450 1em "Inter"'` and `'600 1em "Inter"'` (not `document.fonts.ready`, which can resolve before the font
has started loading). Then `ready` becomes true. In an effect on `[ready]`: call `start()`, collect the cards
(`[data-card]`), and subscribe one frame callback that
- until the intro is over (t > 0.1 + 4 × 0.08 + 0.7; the pass that ends it still writes, so the final values are 1): sets the portrait's opacity to `quartOut(t / 0.8)` and each card's
  `--in` to `quartOut((t − 0.1 − i × 0.08) / 0.7)` (i = 0…3 in DOM order: the cards rise 18 and fade in one after
  another), and sets `data-intro="on"` on `<main>` (not through React, so a re-render never removes it);
- runs the feed (M2).

Before the intro, the cards are hidden by CSS: `.section:not([data-intro]) [data-card] { --in: 0; }`, and the portrait
by its `opacity: 0`. The loop (first event at 0.8 loop time) starts at `INTRO = 1`, once the cards have risen in.

### M10 · Off screen
An `IntersectionObserver` on `<main>` calls `setVisible(entry.isIntersecting)`; the clock skips its frame callbacks
while the section is out of view (time keeps running). Its cleanup disconnects and calls `setVisible(true)`, so
StrictMode's remount never leaves the clock paused.

### Reduced motion (`prefers-reduced-motion: reduce`)
No intro (portrait and cards at full opacity at once), digits jump to their new value without rolling, the marker
jumps, the LIVE dot stays at 0.38, the ring shows a full circle with "IN" (dasharray `"100 100"`, no frame callback),
and the ECG and waveform each draw one still frame (loop time 0.6 for the ECG, 2.5 for the waveform), redrawn by a
`ResizeObserver` on their canvas. The readings still change on the loop.
